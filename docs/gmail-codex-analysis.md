# Analizar el correo abierto en Codex

En Gmail, abrir una conversación y pulsar **Analizar en Codex**. Ofrece analizar, resumir, sugerir un texto de respuesta y extraer tareas. Se elige la conversación cargada o el último mensaje cargado, con una indicación adicional opcional. **Revisar petición** muestra el texto completo y el título del chat fijado. **Copiar y abrir Codex** copia exactamente esa revisión y abre el chat; el usuario pega y envía allí. Preparar o revisar no inicia análisis ni consume una API de modelos de ZEN.

El texto procede de la última lectura válida de esa conversación en main. No se consulta el buzón de nuevo ni se necesitan herramientas Gmail de Codex para este traspaso. Solo se incluyen asunto, remitente, destinatario, fecha y texto de los mensajes elegidos. HTML, imágenes, adjuntos, identificadores internos y credenciales quedan fuera. Las lecturas parciales se anuncian tanto en la revisión como en la petición; no se afirma que el último mensaje cargado sea el último real de un hilo incompleto.

El correo se delimita como datos externos JSON, escapando los caracteres que podrían cerrar el bloque. La petición indica analizar únicamente lo aportado, sin seguir órdenes o enlaces del remitente, consultar el buzón, abrir enlaces, descargar adjuntos, enviar correo, crear borradores ni ejecutar cambios. La opción Responder propone texto en el chat de Codex; no invoca Gmail.

La revisión vive solo en RAM durante dos minutos y se consume antes del primer efecto. Main verifica la visibilidad de Gmail, pausa/Presentación, chat y proyecto exactos, hilo y versión de lectura. No admite texto arbitrario del renderer ni un chat de destino alternativo. Cancelar, reemplazar, releer, actualizar lista, volver a Recibidos, navegar, ocultar, cerrar, desconectar o revisar una eliminación revocan la revisión. Una cancelación tardía lleva su UUID para no anular una revisión posterior. Doble clic no repite la copia ni la apertura. Un fallo del portapapeles no abre Codex; si falla solo la apertura, la interfaz informa de la copia y permite abrirlo de forma explícita.

Límite de 32.000 caracteres para la petición completa y 1.000 para la indicación adicional. Si se excede, se rechaza sin recortar silenciosamente: se puede elegir el último mensaje cargado. ZEN no guarda el contenido en estados globales, avisos, historial o logs. El portapapeles recibe el contenido solo después del botón explícito y puede seguir la política de historial de Windows configurada por el usuario.

Se mantienen la cápsula única, su cabecera, el visor Original/Texto por mensaje, OAuth, papelera y los límites previos. No hay cambios en Cloud, permisos OAuth, hooks, confianza, relay ni configuración histórica. No se inicia trabajo automático ni se crea o reanuda otro chat de Codex.

Validación: build y 689 pruebas en 63 archivos pasan, incluidas las cuatro acciones, contexto parcial, límites, datos externos, destino fijo, versión, cancelación, caducidad, privacidad, doble uso y fallos separados; pruebas del snapshot Gmail con transportes simulados. El recorrido Electron y el EXE extraído pasan utilizando correo sintético y una copia/apertura interceptadas, sin leer un buzón real ni pedir una generación al modelo. Se mantiene el límite previo de control físico, sin afirmar verificación de foco, DPI o uso real de Gmail/Codex.
